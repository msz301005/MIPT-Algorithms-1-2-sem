# B. Заниженная граница (AVL) (2 балла, с ревью)

| | Все языки | (make) Java 17 (Temurin JDK) |

| Ограничение времени | 2 секунды | 6 секунд |
| Ограничение памяти | 256Mb | 512Mb |

| Вывод | стандартный вывод или output.txt | |

Реализуйте AVL-дерево.

Доминик проводит инвентаризацию (опять). Он уверен, что машину можно и нужно сравнить по числу миллисекунд от разгона от нуля до 100 км/ч. Он просит вас помочь ему, а именно, ваш алгоритм должен работать с множеством машин Доминика. Нужно реализовать следующие операции:

- `add(i)` — добавить в множестве машин тачку с разгоном в $i$ миллисекунд (если такая там уже есть, то Доминик отвлекся на семейные разговоры и подсунул вам второй раз ту же самую машину);
- `next(i)` — узнать машину с минимальным временем разгона, не меньшим $i$. Если искомая машина отсутствует, необходимо вывести -1 и попросить Доминика быть внимательнее.

## Формат ввода

Исходно множество машин пусто. Первая строка входного файла содержит число $n$ — количество запросов Доминика ($1 \le n \le 3 \cdot 10^5$).

Следующие $n$ строк содержат операцию. Каждая операция имеет вид:

- `+ i` — `add(i)`
- `? i` — `next(i)`

Если операция `+` идет во входном файле в начале или после другой операции `+`, то она задает операцию `add(i)`. Если же она идет после запроса `?`, и результат этого запроса был $y$, то выполняется операция `add((i + y) % 10^9)`. Это нужно, чтобы Доминик убедился в том, что вы достойный член семьи и не реализовали оффлайн алгоритм.

Во всех запросах и операциях добавления параметры лежат в интервале от 0 до $10^9$.

## Формат вывода

Для каждого запроса выведите одно число — ответ на запрос.

## Пример

**Ввод:**
```
6
+ 1
+ 3
+ 3
? 2
? 1
? 4
```

**Вывод:**
```
3
4
```

Более того, в данной задаче, по мнению Доминика, идеально подойдет AVL-дерево, остальное он не примет в качестве решения!!!

# D. Дерево настроения семьи (3 балла, с ревью)

| | Все языки | (make) Java 17 (Temurin JDK) |
|---|---|---|
| Ограничение времени | 2 секунды | 6 секунд |
| Ограничение памяти | 256Mb | 512Mb |
| Ввод | стандартный ввод или input.txt | |
| Вывод | стандартный вывод или output.txt | |

Реализуйте декартово дерево. Для получения $5$ баллов за задачу можно вместо этого реализовать $B$-дерево или красно-чёрное дерево.

В этой задаче вам предстоит доказать, что вы достойный член семьи. А именно, вам предстоит реализовать сбалансированное дерево семьи.

## Формат ввода

Входной файл содержит описание операций с деревом семьи, их количество не превышает $10^5$. В каждой строке находится одна из следующих операций:

- `insert x` — добавить в дерево члена семьи с настроением $x$. Если такой уже есть, то ничего делать не надо.
- `delete x` — удалить из дерева члена семьи с настроением $x$. Если его там нет, то ничего делать не надо.
- `exists x` — если имеется член семьи с настроением $x$, выведите `true`, иначе `false`.
- `next x` — вывести настроение такого члена семьи, что оно лучше чем $x$, но минимально среди таких или `none`, если такого нет. Это нужно, чтобы понимать, кого на предстоящую гонку можно брать в команду, а кому надо отдохнуть.
- `prev x` — вывести настроение такого члена семьи, что оно хуже чем $x$, но максимально среди таких или `none`, если такого нет.
- `kth k` — выведите $k$-ю величину настроения (нумерация с нуля). Если такого не существует, то выведите `none`.

Все числа во входном файле по модулю не превышают $10^9$.

## Формат вывода

Выведите последовательно результат выполнения всех операций выше. Следуйте формату выходного файла из примера.

## Пример

**Ввод:**
```
insert 2
insert 5
insert 3
exists 2
exists 4
next 4
prev 4
delete 5
next 4
prev 4
kth 0
kth 2
```

**Вывод:**
```
true
false
5
3
none
3
2
none
```

Вы решили собрать всю семью вместе, чтобы узнать, как у них настрой. Пока еще никто не приехал (семья же отвернулась), но вот-вот они будут тут. Вы хотите понимать, каково суммарное настроение у семьи и ее подсемей. Для этого вы хотите уметь следующие вещи:

- `add(i)` — обработать приезд нового члена семьи с настроем $i$ (если он там уже есть, то состав приехавших не изменился, и было введено ошибочное значение);

Если «+ i» идет во входном файле в начале или после другой операции «+», то она задает операцию `add(i)`. Если же она идет после запроса «?», и результат этого запроса был $y$, то выполняется операция `add((i + y) mod 10^9)`.

Во всех запросах и операциях добавления параметры лежат в интервале от 0 до $10^9$.

## Формат вывода

Для каждого запроса выведите одно число — ответ на запрос.

## Пример

**Ввод:**
```
6
+ 1
+ 3
+ 3
? 2 4
+ 1
? 2 4
```

**Вывод:**
```

7
```

# G. Патрули (3 балла)

| | Все языки | (make) Java 17 (Temurin JDK) |
|---|---|---|
| Ограничение времени | 2 секунды | 5 секунд |
| Ограничение памяти | 256Mb | 512Mb |
| Ввод | стандартный ввод или input.txt | |
| Вывод | стандартный вывод или output.txt | |

Хоббс выделил отряды для патрулирования улицы. Для этого он назначил $N$ группировок, каждая из которых обеспечивает безопасность на заданном подотрезке улицы так, что на улице нет участков без присмотра, при этом каждую точку улицы контролирует только одна группировка.

Однако жизнь динамична, поэтому иногда Хоббсу приходится изменять схему регулирования порядка, а именно, он может отдать одно из двух распоряжений ниже.

- Убрать группировку как не заслуживающую доверия.
- Разделить участок на два, как особенно опасный.

Отрезки улицы меняются следующим образом:

- Если участок имеет чётную длину, то он делится на две равные части. Иначе он не делится на две части, длины которых различаются ровно на единицу, при этом часть, которая ближе к началу улицы, имеет меньшую длину.
- Отрезок улицы, принадлежащий уничтоженной группировке, переходит к его соседям. Если у данного участка один сосед, то соседу целиком передается отрезок улицы. Если у него два соседа, после чего каждый из участков ближайшего к нему соседа присоединяет к своему отрезку ближайшую к нему часть.

Гарантируется, что при ходе описанных выше событий длины всех участков улицы остаются не менее двух.

Хоббс прочитал в методичке, что выгодно собирать дань с жителей за поддержание порядка на улице, а именно, этот налог должен быть пропорционален сумме квадратов длин контролируемых отрезков. С вас налог не возьмет, если вы напишите программу, которая будет способна узнавать сумму квадратов длин контролируемых отрезков на старте работы и после каждого события.

## Формат ввода

Первая строка входного файла содержит два целых числа: $N$ и $p$ — исходное количество патрулей и номер подзадачи ($2 \le N \le 10^5$, $0 \le p \le 4$; считайте его просто так).

Вторая строка входного файла содержит $N$ целых чисел $a_1, a_2, \dots, a_N$ — длины исходных отрезков улицы ($1 \le a_i \le 10^4$).

Третья строка входного файла содержит целое число $Q$ — количество событий, происходивших с управлением улицей ($1 \le Q \le 10^5$).

Последующие $Q$ строк содержат описания событий, $i$-я строка содержит два целых числа $e_i$ и $v_i$ — тип события и номер участка, с которого оно произошло. Значение $e_i = 1$ означает, что регулировка, которая после всех предыдущих событий является $v_i$-й по порядку, если считать с единицы от начала улицы, уволена, а значение $e_i = 2$ означает, что этот участок разделился на два.

Гарантируется, что значение $v_i$ не превышает текущее количество участков. Гарантируется, что если осталась одна группировка, она не может быть разогнана.

## Формат вывода

Выходной файл должен содержать $(Q + 1)$ целых чисел, по одному в строке. Первая строка должна содержать исходную сумму квадратов длин отрезков, а каждая из последующих $Q$ строк — сумму квадратов длин участков после очередного события.

## Пример

**Ввод:**
```
4 0
3 5 5 4
5
1 1
2 1
1 3
2 2
1 3
```

**Вывод:**
```
75
105
73
101
83
113
```
