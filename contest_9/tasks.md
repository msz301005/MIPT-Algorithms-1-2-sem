С. любит обучать нейросеть. Для их регуляризации (регуляризации сложности модели) есть такое понятие как dropout. На интуитивном уровне это удаление связей между нейронами в графе нейросети.

А. тоже любит нейросети, но больше он любит спамить С. по самым разным поводам (наиболее популярный вариант — от а к цвету, кстати зовите А. а цвету). Он прознал, что С. прямо сейчас настраивает dropout и постоянно спрашивает, лежат ли два нейрона в одной компоненте связности в его нейросети.

Действия героев записаны в следующем формате:

- операция С. `cut u, v` — в dropout решено убрать ребро между нейронами u и v;
- операция A. `ask u, v` — проверить, лежат ли нейроны u и v в одной компоненте связности.

Известно, что после выполнения всех операций типа cut ребер в графе нейросети не осталось. Найдите результат выполнения каждой из операций ask.

Гарантируется, что граф нейросети не содержит петель и кратных ребер.

## Формат ввода

Первая строка входного файла содержит три целых числа, разделенные пробелами — количество нейронов n, количество связей между ними m и количество операций k (1 ≤ n ≤ 5 · 10⁴, 0 ≤ m ≤ 10⁵, k ≤ 1.5 · 10⁵).

Следующие m строк задают ребра графа нейросети: i-я из этих строк содержит номера концов ребра u_i, v_i (1 ≤ u_i, v_i ≤ n), разделенные пробелами — номера концов i-й связи. Вершины нумеруются с единицы.

Далее следует k строк, описывающих операции в формате выше. Гарантируется, что каждое ребро графа встретится в операциях типа cut ровно один раз.

## Формат вывода

Для каждой операции ask во входном файле выведите на отдельной строке слово "YES", если указанные нейроны лежат в одной компоненте связности, и "NO" в противном случае. Порядок ответов должен соответствовать порядку операций ask во входном файле.

### Пример 1

**Ввод**
```

1 2
2 3
3 1
ask 3 3
cut 1 2
ask 1 2
cut 1 3
ask 2 1
cut 2 3
ask 3 1
```

**Вывод**
```
YES
YES
NO
NO
```

### Пример 2

**Ввод**
```
1 0 0
```

**Вывод**
```
(пусто)
```

### Пример 3

**Ввод**
```

3 1
2 1
4 2
4 1
2 3
3 4
ask 4 3
ask 3 1
cut 3 2
ask 2 3
ask 1 2
ask 1 4
cut 4 3
ask 1 2
ask 4 2
cut 2 4
ask 4 3
cut 4 1
ask 3 2
cut 2 3
ask 2 2
```

**Вывод**
```
YES
YES
YES
YES
YES
YES
YES
```

# E. Скромный и мраморный (3 балла)

| | Все языки | Java 17 (Temurin JDK) | (make) Java 17 (Temurin JDK) |

Схема сектора [ДАННЫЕ УДАЛЕНЫ] представляет из себя связный граф, где вершины — помещения, а коридоры — ребро. Гарантируется, что нет петель и кратных ребер.

Объект SCP-096 — «Скромник», содержится в помещении a, обычно спокоен. Однако когда кто-либо видит лицо SCP-096, будь это непосредственно, на видеозаписи, или даже на фотографии, — он приходит в состояние крайнего эмоционального переживания. SCP-096 закрывает лицо руками и начинает кричать, плакать и невнятно бормотать. Приблизительно через одну-две (1-2) минуты после первого просмотра SCP-096 бежит к увидевшему его лицо (находится в комнате f). Каждый посещенный им коридор назовем **скромным**.

Объект SCP-173 — Скульптура, содержится в помещении b. Объект не может двигаться в то время, когда находится в пределах прямой видимости. При работе с SCP-173 никогда не должен быть нарушен зрительный контакт.

Одновременно с тем, как в f (самом безопасном помещении сектора) агент Г[ДАННЫЕ УДАЛЕНЫ] наблюдает фото лица объекта SCP-096, объект SCP-173 покидает сектор содержания в результате инцидента SCP-173-2 и стремится добраться до f, чтобы [ДАННЫЕ УДАЛЕНЫ]. Каждый посещенный им коридор назовем **мраморным**.

Каждый коридор, оказавшийся одновременно **скромным** и **мраморным**, становится объектом SCP-[ДАННЫЕ УДАЛЕНЫ].

В связи с деятельностью SCP-062 данные о помещениях изменяются (структурно схема не меняется). Так что вам, как сотруднику класса [ДАННЫЕ УДАЛЕНЫ], необходимо узнать, какое минимальное число коридоров сектора могут оказаться одновременно скромными и мраморными в результате движения из пунктов a и b в пункт f для каждого из Q случаев.

## Формат ввода

Первая строка входного файла содержит целые числа: N (1 ≤ N ≤ 10⁵) и M (1 ≤ M ≤ 5 · 10⁵) — количество помещений и коридоров в схеме сектора соответственно.

Третья строка содержит одно целое число f (1 ≤ f ≤ N) — номер самого безопасного помещения.

В следующих M строках находится описание коридоров. В этих строках записаны по два числа u_i и v_i, означающих, что существует коридор, соединяющий помещения u_i и v_i.

Следующая строка содержит целое число Q (1 ≤ Q ≤ 10⁵) — количество возможных схем в ходе деятельности SCP-062. Далее следуют Q строк, каждая из которых содержит два целых числа — номера помещений, a_i и b_i соответственно, где содержатся объекты SCP-096 и SCP-173.

## Формат вывода

Для каждого из Q случаев ваша программа должна вывести минимальное количество коридоров, которые могут оказаться одновременно скромными и мраморными.

### Пример

**Ввод**
```
6 6
1
1 2
2 3
3 4
4 2
4 5
5 6
2
5 6
6 6
```

**Вывод**
```
1
2
```

В первой строке файла даны два числа m и n (1 ≤ m, n ≤ 4000) — размеры долей. Каждая из следующих m строк содержит список ребер, выходящих из соответствующей вершины первой доли. Сумма всех K_i во входном файле не превосходит 500 000. Последняя строка файла содержит некоторое максимальное паросочетание в этом графе — m чисел 0 ≤ L_i ≤ n — соответствующая i-й вершине первой доли вершина второй доли, или 0, если i-я вершина первой доли не входит в паросочетание.

## Формат вывода

Первая строка содержит размер минимального контролирующего множества. Вторая строка содержит количество вершин первой доли S, после которого записаны S чисел — номера вершин первой доли, входящих в контролирующее множество, в возрастающем порядке. Третья строка содержит описание вершин второй доли в аналогичном формате.

### Пример

**Ввод**
```

2 1 2

```

**Вывод**
```
2
1 1
1 2
```
